# 蔗糖的消息防抖~

把用户没说完的话攒在一起再交给模型。**图片也算话。**

## 解决什么

以前用户发一张图 → 机器人回一次；再补一句"这猫好丑" → 机器人又回一次。两段回复各说各的，前言不搭后语。

现在这两条会并成**同一条消息**：模型拿到的是「一张图 + 一句话」，只回一次。

## 合并规则

| 用户操作 | 合并结果 |
|---|---|
| 文字 + 文字 | `我想买个` + `键盘` → `我想买个\n键盘` |
| 图 + 文字 | 组件链 `[Image, Plain]`，文本只剩「这猫好丑」 |
| 图 + 图 | 组件链 `[Image, Image]`，文本用引导语 |
| 图 + 图 + 字 | 组件链 `[Image, Image, Plain]` |
| 纯图 | 文本填 `image_only_prompt`（默认「看看这个」） |

图片的占位符（`[图片]`）会从文本里剥掉，避免和真实图片重复。

## 两种节奏

- **纯文字**：`debounce_ms` 默认 `0` = 首条立刻进模型。后续消息到达时取消上一轮、合并重生成，所以首字不卡。
- **含图片**：`image_debounce_ms` 默认 `1000`。发图后多等一秒，留给用户把配文打出来。图片本来就慢，这一秒感知不明显，但能把"分两次回"的概率压到最低。

## 图片为什么要复制一份

原消息被取消后，平台侧的临时图片文件随时会被清理。如果只是引用旧组件，合并后的请求会拿到一个已经不存在的路径。

所以收到图的第一时间就落到 `data/plugin_data/astrbot_plugin_sugar_debounce/media/`，按内容哈希命名去重，15 分钟没被引用就自动清掉。

## 配置

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | on | 总开关 |
| `merge_images` | on | 关掉退回纯文本合并 |
| `image_debounce_ms` | 1000 | 含图消息的缓冲窗口 |
| `debounce_ms` | 0 | 纯文本静默窗口，设 300~800 会等用户打完再发 |
| `max_messages` | 8 | 一次最多合并几条，0 = 不限 |
| `max_images` | 9 | 一次最多几张图，0 = 不限 |
| `max_chars` | 4000 | 合并文本上限，0 = 不限 |
| `image_only_prompt` | 看看这个 | 只发图不打字时的提示词 |
| `ignore_prefixes` | `/` `!` | 这些开头的消息不合并，直接放行 |

## 不会合并的情况

- 上一轮**已经发出回复**了（`result.chain` 非空）
- 上一轮已经开始调工具（`tools_started`）
- 上一轮是流式输出且已开流
- 超过 `max_messages` / `max_images` / `max_chars`
- 消息以命令前缀开头
- 消息里含 `Reply`、`Record`、`Forward` 等不适合并入的组件

## 和 astrbot_plugin_message_merger 的关系

机制同源（零等待 + 取消重生成），但那边只认 `Plain` 和 `At`，图片消息会被直接放行，所以图文仍然分两次回。

**两个都开必然打架**（都会改写 `message_str`、都会取消对方的 pipeline）。用这个就把旧的关掉。
